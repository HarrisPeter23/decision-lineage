# Cross-Meeting Decision Lineage: benchmark, systems and evaluation

Code, data and outputs for the paper *Why Did the Decision Change? A Benchmark and Evaluation of Retrieval-Augmented Systems for Cross-Meeting Decision Lineage* (anonymous submission).

The task: given the transcripts of a series of meetings and a question, explain **why** a decision changed, citing every claim to what was said. This repository contains:

- **The benchmark.** 36 synthetic meeting series (113 meetings, 293 gold chain links, 373 questions with deterministic answers), split into DEV (14 series) and TEST (22 series). It also has an AMI case study: 5 series, 20 meetings, 43 gold links and 50 questions.
- **The reference pipeline** (`argdecisionlineage/`) and three baselines (`baselines/`): vector RAG, our EvoWiki-style re-implementation, and Graphiti used as released.
- **The evaluation code.** This includes the primary metric, cited-lineage F1 (`eval/lineage_f1.py`), which uses no judge.
- **The pre-registration** (`reports/FREEZE.md`), the log of every later change (`reports/deviations.md`), and the result files behind every table and figure in the paper.

## Setup

Python 3.12. CPU is enough for everything except re-running the LLM stages.

```
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install --index-url https://download.pytorch.org/whl/cpu torch==2.15.0
pip install -r requirements.txt
python -m pytest -q tests                            # 57 passed, 1 xfailed
```

The embedding model (`sentence-transformers/all-MiniLM-L6-v2`, revision 1110a243fdf4) and the NLI model (`cross-encoder/nli-deberta-v3-small`, revision fa2804872c3b) download from Hugging Face on first use. After that, set `HF_HUB_OFFLINE=1`.

## Reproducing the paper

There are three levels. Levels 1 and 2 were checked on this release: every output listed below was regenerated byte-identical to the shipped file.

**Level 1: tables and figures from the result files (seconds, CPU).**
```
python paper/make_tables.py        # paper/tables/*.tex  (Tables: TEST primary, TEST means, stage loss; DEV tables)
python paper/make_figures.py       # paper/fig_example_final.tex  (Fig. 1)
python paper/make_supp_example.py  # supplementary worked example
```

**Level 2: statistics and scores from saved model outputs (minutes, CPU).**
```
export HF_HUB_OFFLINE=1
# re-score a system from its raw generations (shown for ours; the same script scores every system)
python eval/phase5_score.py --tag lineage@test_k1 --stage parse --scope test_k1 --size 1 \
  --gen-dir results/phase7/gen/adl-p7-gen-mine/out --score-root results/phase7/score \
  --retrieval results/phase7/retrieval/lineage@test_k1.jsonl --nli-cache results/phase7/nli/cache_p1.jsonl
python eval/phase5_score.py --tag lineage@test_k1 --stage final --scope test_k1 --size 1 \
  --score-root results/phase7/score --judge results/phase7/judge/out
# other systems: same two commands with --tag <system>@test_k1 and its --retrieval file; --gen-dir is
#   adl-p7-gen-mine (lineage, no_typing, no_conflict_resolution, static_graph), adl-p7-gen-evo-p1 (evowiki_style),
#   adl-p7-gen-graphiti-p1 (graphiti), adl-p7-gen-vrag-p1 (vector_rag); all seven reproduce byte-identically
python eval/phase7_stats.py          # H1 primary and secondary tests -> results/phase7/h1_tests.json
python eval/phase7_extra.py          # failure-free subset (D-35), H2, ablations -> results/phase7/extra_tests.json
python eval/phase7_stage_loss.py     # where the lineage is lost -> results/phase7/stage_loss.json
python eval/phase7_extract_eval.py   # extraction DEV vs TEST -> results/phase7/extract_eval.json
python eval/phase7_ami_summary.py    # AMI case study -> results/phase7/ami_summary.json
python eval/phase7_calib_report.py report                                              # Gemini/Granite/NLI calibration
python eval/phase7_pairwise.py report --split test --granite results/phase7/pairwise/granite   # pairwise
python eval/phase7_failure_analysis.py; python eval/diag_argument_layer.py; python eval/diag_versions.py   # post-hoc
python eval/lineage_f1.py            # DEV cited-lineage F1 and DEV ablations -> results/lineage_f1_dev.json
```
Statistics use a paired bootstrap over TEST sets: 10,000 resamples, seeded, with Holm correction. Reruns give identical numbers. TEST failure counts are in `results/phase7/failures.md`.

**Level 3: re-running the LLM stages (GPU).** Extraction, the baselines' build steps, generation, the judge and the NLI checker all ran as Kaggle notebooks on 2 x T4, with Ollama 0.40.13. They used about 27 GPU-hours for the TEST week. The builders are `runtime/kaggle/*/build.py`. Each writes a kernel directory, and the kernels that actually ran are kept under `runtime/kaggle/*/kernels/`. Kernel ids use the placeholder `KAGGLE_USER`; replace it with your Kaggle username before `kaggle kernels push`. Graphiti also needs Neo4j Community 5.26.17, which the kernel installs and which is not redistributed here. Gemini calls (calibration and pairwise only) read `GEMINI_API_KEY` from the environment or a local `.env` file, which is not included. LLM outputs at temperature 0 can still vary across hardware and versions, so a Level 3 rerun is not expected to be byte-identical. Levels 1 and 2 are.

## Pre-registration

`reports/FREEZE.md` was frozen at commit `309776048cd8ee9ed09fba341a269514ffdd2f53` (2026-11-08) of the authors' development repository, before any TEST run. This release is a fresh repository without that history. The header of `FREEZE.md` gives the commit, its date and the SHA-256 of the frozen text. You can check the hash with:
```
python -c "import hashlib;b=open('reports/FREEZE.md','rb').read();print(hashlib.sha256(b[b.index(b'-->\n')+4:]).hexdigest())"
```
Everything changed after the freeze is in `reports/deviations.md`, and analyses that were not pre-registered are labelled post-hoc there and in the paper.

## Limitations

- **Synthetic data shaped by our schema, from one writer.** All TEST series were written by one LLM, and a control writer from another model family could not be produced, so writer leakage is not controlled. The arcs follow the schema our pipeline uses, and the question router matches the benchmark's templates.
- **Optimistic DEV.** DEV was used for repeated tuning, and F1 fell from DEV to TEST for every system, most for ours.
- **Labels are mostly LLM-verified.** The judge panel verifies content and speaker, not roles. The authors' hand check covers 40 of 336 gold links.
- **Explanation quality has no validated measure.** Cited-lineage F1 measures evidence localization, not faithfulness or the correctness of the explanation, and it may favour systems that cite narrow spans. No judge qualified for sentence faithfulness.
- **Small samples.** TEST has 22 sets. The AMI study has five series, its gold was drafted by an LLM, and its dates are synthetic offsets.
- **Scale and re-implementation.** All systems use one local 14B model. EvoWiki-style is our re-implementation (see `baselines/evowiki_style/SIMPLIFICATIONS.md`), so conclusions about it may not transfer to the original EvoWiki.
- **Not for training,** and not evidence about real organisations. All people and organisations in the synthetic data are fictional.

## Notes on this release

- Some files refer to internal working documents that are not released: development checkpoint and phase reports (`CHECKPOINT_*.md`, `reports/phase*.md` other than `phase3_configs.md`), the scope note `SCOPE_4WEEK.md`, `paper_notes.md`, and the gold audit (`audit/`, deviation D-44). D-47 corrects D-44: that audit was performed by LLMs, not humans, and it is neither released nor reported in the paper. The decisions those documents record that matter for the results are restated in `FREEZE.md` and `deviations.md`. `FREEZE.md` is frozen and was not edited to remove these references.
- Left out to save space, all of them regenerable: Ollama server logs (`ollama_*.log`), the DEV NLI caches (`results/phase6/nli/cache*`, `ordered*`), and the NLI input pair files (`pairs_*.jsonl`). The TEST and AMI NLI caches needed for Level 2 are included.
- Third-party PDFs cited in the documentation (`baselines/papers/`) are not redistributed. The raw AMI archive (`ami_public_manual_1.6.2.zip`) is not included either; download it from the AMI corpus site if you want to rebuild `data/ami/` with `eval/ami_ingest.py`.
